# pilot fork of Moli

pilot is a fork of [lexmount/moli](https://github.com/lexmount/moli), made into a browser that [Playwright MCP](https://github.com/microsoft/playwright-mcp) can launch and drive as if it were Chromium. It runs headless, or headful with a "watch the agent" window. The deliberate choices are in [DECISIONS.md](DECISIONS.md); the CDP and launch contract pilot targets is in [docs/playwright-contract.md](docs/playwright-contract.md).

## Remotes

| Remote | URL | Use |
|---|---|---|
| `origin` | https://github.com/WSAdam/pilot | Our fork (renamed from `moli`). Only the `pilot gate` workflow runs here. Upstream's own workflows stay disabled, because they target its self-hosted runners. Each finished unit lands here once its gate run is green. GitHub paused Actions on this fork for its usage from 2026-11-10 to 2026-11-13, so gate runs are batched. |
| `upstream` | https://github.com/lexmount/moli | Fetch-only source of release tags. Its push URL is set to `DISABLED-pilot-never-pushes-to-moli`. |

**Base:** upstream main `51d6d1ee3` (2026-11-02), which is 113 commits past `v1.1.20`.

## Taking an upstream release

1. `git fetch upstream --tags`
2. `git merge <tag>` on `main`. Never rebase `main`: it is published.
3. Resolve conflicts using the tests as the oracle. Read both sides' tests, keep a resolution that satisfies both, and re-run the fixtures each `pilot-core` patch lists below.
4. Run `cargo fmt --all`, then `cargo clippy --workspace --all-targets --all-features -- -D warnings`, then `cargo nextest run --no-fail-fast`, then the pilot smoke groups. All of them must be green before the merge commit lands.
5. If upstream now fixes something a `pilot-core` patch covers, drop the patch and remove its row below.

## Fork-owned crates

| Crate | Purpose |
|---|---|
| `pilot` | The `pilot` binary: reads Chromium's command line as Playwright passes it (`pilot/src/argv.rs`, fixtures captured from Playwright 1.65 and MCP 0.0.84 in `pilot/tests/fixtures/`) and runs Moli's protocol server with real layout over the pipe or port it asks for (`pilot/src/serve.rs`). Claims Chrome on the host OS as its identity (`pilot/src/identity.rs`). Claims the profile like Chromium (`SingletonLock`, exit 21 when in use) and announces a port endpoint (`DevTools listening on`, `DevToolsActivePort`) in `pilot/src/profile.rs`. Later: the choice between headless and the window |
| `pilot-window` | The "watch the agent" window (M3): a second CDP client of the same browser over `LocalCdpConnector`, opened by `pilot` whenever `--headless` is absent (`pilot/src/headful.rs`; `PILOT_NO_WINDOW=1` turns it off; without a display pilot runs headless). `app.rs` is the winit + softbuffer window on the main thread with chrome drawn by vello_cpu and system-font labels from skrifa outlines (`text.rs`). Pure parts: chrome layout and window-to-page coordinates (`geometry.rs`), the tab strip reduced from `Target.*` events (`tabs.rs`), screencast frame decoding and scaling (`frame.rs`), `Input.*` parameters for a human's mouse and keys (`input.rs`), the agent-activity indicator (`agent.rs`); and `controller.rs`, its CDP side: follows the agent's tabs, attaches to the shown one, runs its screencast with acks, forwards navigation and `Input.*`, and stops the browser when the window closes (tested against a real in-process browser in `tests/controller.rs`) |
